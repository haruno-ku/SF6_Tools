## 自動入力とは何か、何をしていないか

`0.3.0-diagnostics` は**入力を注入しない**。`Provenance` が未計測のボタンビットを
使う経路を塞いでいて、この実行でもそれは一度も開いていない。

「自動」と書いてあるものは **OS レベルのキーボード入力**（SendInput）で、
人間がキーボードを叩くのと同じ経路。ゲーム自身のキーバインドを通るので
「存在しないボタンを押す」ことは起きない。**フレーム精度は無い。**

その限界がデータに出ている:

- `probe_a_damage-...144239Z` の不一致2件は `hits 1 / field 400 / hpDelta 800`、
  ちょうど2倍。繋がったコンボではなく**短い間隔で入った別々の単発**を
  probe が1サンプルにまとめた形。**ゲームの挙動ではなく入力の質の問題**
- 同じ自動入力でも、1発ずつ間隔を空けた実行では**14件中14件が一致**した

だから Probe A の結果としては**人間の実行（144757Z）を採る**。

Probe B / C / D は「誰が押したか」に依存しない量（フックの発火回数、
リセットの所要時間、出た action_id）なので、自動入力でも同じ値になる。

## Probe D が結論に達していない理由

`min_observed = 20`（`core/CatalogAudit.lua:130`）に対して観測 18 種類。
不足しているのは種類数だけで、**RUNBOOK が赤信号と呼ぶ状態ではない**
（「観測した action_id が1つもカタログに無い」＝ 実際は 11/18 が一致）。

一致しなかった7件のうち `1` `6` `9` は立ち・歩きの状態で、
技のカタログが名前を持っていなくて当然のもの。

SA と OD必殺技を当てれば 20 を超えて conclusive になる。
